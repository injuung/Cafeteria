## 1. 목표 수준

`[문서]` 완전 자동화가 아니다. 담당자가 수작업으로 만드는 결과를 100점이라 할 때 **60~70점 초안**을 만들어 "손만 보면 되는" 상태로 넘긴다.

애매한 판단은 무리해서 결정하지 말고 검증 리포트에 남겨 담당자 확인 항목으로 둔다.

## 2. 하루 식단 구조

`[문서]` 하루는 **6칸**이다.

```
밥 1  +  메인 1  +  서브1 1  +  서브2 1  +  김치 1  +  국 1
```

- 서브는 2개다. 김치를 서브에 포함해 3개로 세지 않는다.
- 서브1은 메인급으로 관리하고, 서브2는 선호 반찬·나물·샐러드·김류가 들어가는 자리다.

### 2-1. 보조 메뉴 (`&` 항목)

`[확정]` 메뉴명이 `&`로 시작하는 항목은 **독립 메뉴가 아니라 직전 메뉴에 딸린 보조**다. 소스·드레싱·양념장·곁들임이 여기 해당한다.

```
한입새우튀김        ← 메인 (1칸 차지)
& 레몬크림소스      ← 보조 (칸을 차지하지 않음)
```

식단표에는 두 줄로 표기되지만 하루 구조는 여전히 6칸이다.

- 보조에는 자리(slot)를 부여하지 않는다.
- 로테이션 주기 계산과 자리 배정 통계에서 제외한다.
- **알레르기는 부모와 한 몸으로 본다.** 별도 메뉴로 중복을 이중 계산하지 않는다. 부담이 크면 다른 반찬으로 보완한다.

14개월 데이터에서 보조는 133건, 고유 37종이며 모두 직전 메뉴에 귀속된다(고아 0건).

### 2-2. 배치 우선순위

`[문서]` 반드시 이 순서로 결정한다.

```
메인  →  국  →  서브1  →  서브2  →  밥  →  김치
```

메인이 절대 기준이다. 충돌이 생기면 **메인을 고정하고 나머지를 바꾼다.**

### 2-3. 자리 구분은 데이터에 없다

`[문서]` 식단표에는 메인/서브 구분 컬럼이 없다. 과거 식단표에서 **메뉴가 놓인 자리(행 위치)**를 학습해 분류해야 한다. 메뉴명만으로 "김치전이 김치인가 반찬인가"를 판단하려 하지 마라.

일자별 생산일지 시트에는 `구분` 열이 있고 다음과 같이 대응한다.

| 생산일지 표기 | 논리 자리 |
|---|---|
| 밥 | 밥 |
| 국 | 국 |
| 메인 | 메인 |
| 반찬1 | 서브1 |
| 반찬2 | 서브2 |
| 반찬3 | 김치 |

## 3. 하드 제약 (위반 0건이어야 한다)

### 3-1. 같은 날 주재료 중복 금지

`[문서]` 메인 ↔ 서브1 ↔ 서브2 ↔ 국 사이에 주재료가 겹치면 안 된다. (밥·김치는 제외)

> 이유는 다양성이 아니라 **알레르기·종교 사유로 특정 재료를 못 먹는 아이가 그날 아예 먹을 게 없어지는 상황을 막기 위해서**다.

**주재료 판정 기준** `[확정]`

어떤 재료를 "주재료"로 볼지는 다음 세 규칙으로 정한다.

1. **조미료에서 온 성분은 주재료가 아니다.**
   간장·국간장·양조간장·된장·고추장·춘장·새우젓·멸치육수·멸치액젓·액젓·굴소스·사골엑기스·치킨스톡·다시다·대두유·참기름·들기름·짜장분말·카레분말·밥새우·건새우·두절건새우·소고기다시·쇠고기다시·멸치다시·가쓰오·우스터·조개다시·굴 — 총 29개
2. **메뉴명에 언급된 재료는 비율과 무관하게 주재료로 인정한다.**
3. **그 외에는 자재사용내역상 비율이 10% 이상일 때만 주재료로 인정한다.**

담당자 확인 문구:
> "떡갈비에는 돼지고기가 주재료이며, 소고기는 부수적으로 포함되는 식재료이므로 중복으로 보지 않는다. 궁중떡볶이에 소고기도 5% 미만 부재료로 사용되기에 중복으로 보지 않는다."

적용 예시

| 메뉴 | 자재사용내역 | 주재료 판정 |
|---|---|---|
| 미니떡갈비 | 돼지고기 25.06%, 소고기 5% | 돈육만 (소고기 5% < 10%, 이름에도 없음) |
| 소고기탕국 | 무 15%, 소고기 8%, 두부 5% | 우육 (이름에 있으므로 8%도 인정) |
| 세멸치엿장조림 | 멸치 79.9%, 대두유, 간장 | 어류만 (간장의 대두는 조미료) |
| 고사리나물 | 고사리 88.6%, 마늘, 대파, 국간장 | 없음 |
| 호박새우젓볶음 | 호박 75%, 새우젓 | 없음 (새우젓은 조미료) |

**주재료 분류 11종** `[추정]`

```
돈육 · 우육 · 계육 · 오리 · 난류 · 새우 · 연체 · 두류 · 어육 · 어류 · 가공육
```

이 11종 중 하나라도 겹치면 위반으로 본다.

> 검증: 이 기준으로 담당자 실제 편성을 검사하면 최근 1년 위반이 월 2~3건 수준이다. 조미료를 배제하지 않으면 월 25~29건으로 튄다.

### 3-2. 튀김 2개 금지

`[문서]` 같은 날 튀김류가 두 가지 이상 나오면 안 된다.

### 3-3. 최우선 알레르기 하루 2개까지

`[확정]` 알레르기 번호 **1(난류) · 4(견과류) · 9(새우) · 18(조개류)** 는 같은 날 **2개 메뉴까지만** 허용한다. 3개 이상이면 위반이다.

나머지 번호는 상한을 두지 않는다. 특히 10(돼지고기)·15(닭고기)·16(쇠고기)는 대부분의 식단에 들어갈 수밖에 없으므로 **번호 중복이 아니라 §3-1 주재료 중복으로 관리한다.** 13(아황산류)는 통조림 보존료라 무시한다.

> 최근 1년 471일 중 3개 이상 겹친 날이 22일(4.7%) 있었다. 즉 이 제약은 담당자 실적보다 약간 엄격하다.

### 3-4. 월간 상한

`[문서]`

| 항목 | 상한 | 목표 |
|---|---|---|
| 완조리(완제품) 메뉴가 **메인**으로 들어가는 경우 | 월 3회 | 월 2회 |
| 덮밥소스류 | 월 2회 | — |

서브 자리에 오는 완제품(도시락김·조각피자 등)은 이 상한과 무관하다. **메인 자리에만 적용한다.**

### 3-5. 김치 중복 회피

`[문서]` 김치는 배추김치·깍두기·백김치·열무김치가 자유롭게 반복된다. 단 **다른 메뉴에 김치 종류가 재료로 쓰이면 그 김치를 피한다.**

```
그날 메인이 "참치깍두기볶음"  →  김치는 깍두기 대신 배추김치
그날 국이  "돈육김치찌개"     →  김치는 배추김치 대신 깍두기 또는 백김치
```

## 4. 로테이션 주기

`[문서]` + `[추정]` (구체적 일수는 잠정치)

| 자리 | 최소 간격 (이보다 짧으면 탈락) | 목표 간격 |
|---|---|---|
| 메인 | 60일 | 82일 |
| 서브1 | 60일 | 82일 |
| 국 | 60일 | 82일 |
| 서브2 | 14일 | 30일 |
| 샐러드류 (서브1·서브2 중) | 60일 | 90일 |
| 밥 | 제한 없음 | — |
| 김치 | 제한 없음 | — |

문서 원문은 "메인·서브1·국은 2.5~3개월, 샐러드류는 3개월 목표"다. 2.5개월은 약 75일이지만 후보 부족을 우려해 최소선을 60일로 완화했다. **이 숫자는 튜닝 대상이다.**

서브2가 짧은 이유는 문서의 "선호 메뉴는 월 1~2회, 다음 달에도 반복 가능" 때문이다.

### 4-1. 국의 예외

`[문서]`

- **미역국류는 주 1회**를 넘지 않는다. 동시에 주 1회 편성을 지향한다(가점).
- **소고기미역국·소고기무국**은 선호도가 높아 로테이션과 무관하게 **월 2회**까지 허용한다.
- **메인이 완조리 제품이거나 닭고기인 날에는 소고기가 들어간 국을 의도적으로 배치한다.**
  "여기는 냉동식품만 쓰는 곳이 아니구나" 하는 학부모 안심 효과를 노린 배치다. 단순 선호가 아니라 의도된 패턴이므로 규칙으로 구현한다.

## 5. 메뉴 풀 — 무엇을 후보로 쓸 것인가

### 5-1. 활성 판정

`[확정]` **최신 시점 기준 1년 내에 식단표에 한 번도 등장하지 않은 메뉴는 퇴출된 것으로 본다.**

- 레시피북에서 삭제된 것은 삭제된 채로 둔다. 복원하지 않는다.
- 3개월 미출현 정도로는 폐지 판정을 하지 않는다(정상 로테이션 범위).

2026-09-01 기준 집계

```
레시피 ID 총           762종
  ├ 활성                391종   ← 최신 레시피북 등재 + 1년 내 출현
  ├ 활성(레시피북 미등재)  53종   ← 1년 내 출현했으나 레시피북에 없음
  ├ 비활성(1년 미출현)   162종   ← 퇴출
  └ 폐지                156종
보조(&) 레시피          37종    ← 자리 후보에서 제외
사용여부 X              52종    ← 담당자가 끈 메뉴
────────────────────────────
생성기 후보 풀          372종
```

### 5-2. 사용여부 (O/X)

`[확정]` 마스터 시트에 `사용여부` 열을 두고 **담당자가 직접 O/X로 관리**한다.

- `X`로 바꾸면 그 메뉴는 초안 생성에서 제외된다.
- 클레임·뉴스 이슈로 당분간 빼야 할 메뉴도 여기서 `X` 처리한다. **별도 블랙리스트를 두지 않는다.**
- 신메뉴는 시트 맨 아래에 행을 추가하고 대표명·자재사용내역·알레르기번호·기준중량 네 칸만 채우면 된다.
- 생성기는 `사용여부 = O`인 메뉴만 후보로 쓴다. 성인식 변형 대상으로도 쓰지 않는다.

담당자 확인 문구:
> "(블랙리스트는) 없다. 이런 건 비규칙적이라서 그때마다 알려주는 수밖에 없다."
> "그때그때 메뉴 추가 및 삭제를 할 수 있으면 좋겠다."

### 5-3. 마스터 갱신

`[확정]` 레시피북은 계속 변한다. 2026-03 → 2026-09 사이에 신규 72종·삭제 55종이 발생했다.

| 주체 | 주기 | 할 일 |
|---|---|---|
| 담당자 | 수시 | 사용여부 O/X 토글, 신메뉴 행 추가 |
| 개발측 | 분기 1회 | 새 생산일지로 자동 컬럼(출현이력·자재내역·별칭 등)만 재계산 |

**재동기화 시 담당자가 손댄 `사용여부`와 직접 추가한 행은 반드시 보존한다.**

## 6. 요일·캘린더 규칙

### 6-1. 도시락김

`[문서]` **금요일에만, 월 2회.** 조리·전처리가 필요 없고 포장팀이 미리 작업할 수 있어 조리팀 연차 사용을 수월하게 하기 위한 배치다.

서브2 자리에 들어간다. 13개월 관측에서 12개월이 금요일이었고 월 1~2회였다.

### 6-2. 생일파티 특식일 ⚠ 문서와 다름

`[확정]` **매월 3주차 금요일**이 생일파티 특식일이다.

> 인터뷰 문서는 "볶음밥 + 스파게티 편성"이라고만 했으나, 담당자 정정 문구는 다음과 같다.
> **"볶음밥과 스파게티 등 특식을 제공함"이 정확한 정의다.** 즉 고정 조합이 아니라 특식 범주다.

**구성** — 국이 없고 김치 대신 수제피클, 디저트가 추가된다.

```
볶음밥류  +  스파게티면 + 소스  +  치킨류  +  찐빵 또는 샐러드  +  수제피클  +  디저트
                                                              ── 국 없음 ──
```

관측된 8회 예시

```
2025-09-19  소고기볶음밥, 스파게티면(미트소스), 뿌링클치킨, 캐릭터찐빵, 수제피클, 젤리스틱포도
2025-10-17  버터계란볶음밥, 스파게티면(베이컨토마토소스), 치킨가라아게, 과일샐러드, 수제피클, 딸기짜요
2026-03-20  소고기볶음밥, 스파게티면(미트소스), 눈꽃치즈치킨, 캐릭터찐빵, 수제피클, 딸기짜요
2026-04-17  버터계란볶음밥, 스파게티면(베이컨토마토소스), 용가리치킨너겟, 카프레제샐러드, 수제피클, 젤리스틱포도
```

## 7. 완조리(완제품) 판정

`[확정]` 레시피북에 완제품 표시 컬럼이 없으므로 다음 세 신호를 점수화해 판정한다. **합계 5점 이상이면 완제품이다.**

| 신호 | 점수 | 설명 |
|---|---|---|
| A. 자재사용내역이 `제품명[성분,성분…]` 형태 | 2점 | 제조사 성분표를 그대로 옮긴 흔적 |
| A-2. 그 주재료 비율이 50% 이상 | +2점 | |
| B. 일자별 시트에서 중량(g)이 아닌 수량(EA)으로 관리 | 2점 | |
| C. 메모의 브랜드 제품명이 메뉴명과 일치 | 3점 | |

판정 예시

```
5점 이상 = 완제품
  치킨너겟       메모 "치킨너겟(하림)"
  용가리치킨너겟   메모 "용가리치킨(하림)" + EA 관리
  불고기피자      메모 "과드라불고기피자(M&F)"
  생선까스       성분표블록 95% + EA 관리 + 메모 일치

4점 = 완제품 아님 (직접 조리로 분류)
  보쌈수육       돈수육 제품 99%를 사서 썰어 냄
  족발부추무침     족발 제품 95%에 부추를 넣고 무침
  닭살떡조림      닭고기 제품 75%에 떡을 넣고 조림
  훈제닭볶음      훈제닭 80%에 양배추를 넣고 볶음
```

담당자 확인 문구:
> "5점 이상 = 완제품으로 해줘."

**주의** — 신호 C는 메모가 비어 있는 신메뉴에는 쓸 수 없다. 신메뉴는 담당자가 수동으로 완제품 여부를 지정할 수 있어야 한다.

**주의** — 신호 B(EA 관리)를 단독으로 쓰면 안 된다. 계란말이·주먹밥·채소계란찜처럼 직접 조리하면서 개수로 세는 메뉴가 섞인다.

## 8. 메뉴 명칭 — 중복 판정의 함정

`[확정]` **메뉴명으로 동일 메뉴 여부를 판단하면 안 된다.**

같은 날 "볶음+볶음", "찜+찜"처럼 조리방식이 겹치면 메뉴명이 단조로워 보이므로, 담당자는 **레시피는 그대로 두고 이름만 바꾼다.**

```
돈사태양념찜 + 어묵채소찜  →  앞을 "돈사태양념볶음"으로 변경
북어콩나물무침 ↔ 북어콩나물조림     (같은 레시피, 달마다 이름만 다름)
짜장덮밥소스 → 소고기짜장덮밥소스 / 유니짜장덮밥소스
```

> 담당자 확인 문구: "메뉴 구성상 같은 조리 방법일 경우 이름만 변경"

### 8-1. 구현 원칙

- **중복 판정과 로테이션 주기 계산은 메뉴명이 아니라 레시피 ID 기준으로 한다.**
- 레시피 ID는 자재사용내역을 정규화해 부여한다.
- 조리방식 중복은 **금지가 아니라 감점**이다. 어느 정도 허용하되 반복되면 명칭 변경으로 해소한다.

### 8-2. 개명은 제거 대상이 아니라 활용 자산

`[확정]` 같은 레시피를 다른 이름으로 내보내는 것은 **전처리·자재발주·조리라인을 늘리지 않고 체감 다양성만 올리는 장치**다.

따라서 시스템은 두 레이어를 가져야 한다.

```
[정체성 레이어]  레시피 ID   ─  중복 판정 · 로테이션 · 주재료 충돌 · 알레르기
                              메뉴명은 보지 않는다
[표기 레이어]    별칭 풀     ─  출력 시 이름 선택
                              조리방식 중복 회피 · 직전 표기명 회피
```

2026-09 기준 별칭 2개 이상인 그룹이 87개 있다.

```
돼지갈비찜  ←  매운갈비찜 / 매콤돼지갈비양념찜 / 매콤돼지갈비찜 / 양념돼지갈비찜
캐릭터찐빵  ←  바다동물모양찐빵 / 숲속친구들찐빵 / 이솝찐빵
맑은아귀국  ←  순살아귀탕 / 맑은아귀탕 / 순살아귀콩나물국
```

### 8-3. 확정된 개명 2건

`[확정]` 2026-09 담당자 회신

| 이전 이름 | 현재 이름 | 사유 |
|---|---|---|
| 햄버거스테이크 | **갈릭햄버거스테이크** | 갈릭스테이크소스를 뿌려 제공하는 방식으로 변경 |
| 순살아귀탕 | **맑은아귀국** | 명칭 변경 |

## 9. 유아식 vs 성인·초등식

`[문서]` **유아식이 베이스다.** 유아 식단표를 먼저 완성한 뒤 변형해 성인·초등(글로벌리더스 등) 식단을 만든다.

### 9-1. 학습 창

`[문서]` 변형 패턴은 **최근 6개월**(3개월 단위 × 2회분) 유아식/성인식 비교로 학습한다. 그 이상 오래된 데이터를 넣으면 "우연히 6개월에 한 번 이렇게 됐네" 같은 무의미한 규칙까지 학습하므로 금지한다.

### 9-2. 변형 유형과 처리 ⚠ 문서와 다름

> 인터뷰 문서는 "**간·매운맛 조정이 대부분**이며 메뉴 자체를 바꾸는 건 **월 1회 정도**"라고 했다.
> 14개월 전수 대조 결과는 정반대다.

같은 날 유아식과 성인식이 다른 경우 **308건**의 내역

| 유형 | 건수 | 비율 | 처리 |
|---|---|---|---|
| ④ 메뉴 자체 교체 | 178 | 58% | **재현하지 않음** |
| 김치 교체 | 62 | 20% | §9-4 |
| ① 같은 레시피, 표기만 변경 | 29 | 9% | 재현 |
| 밥 교체 | 22 | 7% | **재현하지 않음** (§9-5) |
| ③ 양념·재료 추가 | 9 | 3% | 재현 |
| ② 매콤/얼큰 접두만 | 8 | 3% | 재현 |

담당자가 설명한 각 유형의 배경

| 유형 | 담당자 설명 |
|---|---|
| ① 표기만 변경 | "메뉴 구성상 같은 조리 방법일 경우 이름만 변경" |
| ② 매콤/얼큰 | "레시피 같은데 고춧가루 더 들어감. 생산일지에는 수기로 수정" |
| ③ 양념·재료 추가 | "②와 비슷한 상황이나 레시피가 생산일지에 기재되어 있음" |
| ④ 메뉴 자체 교체 | "제공받는 업체에서 장기간 이용하다 보면 식상하다는 피드백이 올 경우 전체적으로 바뀌는 경우 있음" / "메뉴 구성에 따라 성인식으로 제공하기 부족한 경우 바뀔 수 있음" |

### 9-3. 재현 대상 — 세 유형만

`[확정]` 성인식 변형으로 **인정하는 관계는 다음 세 가지뿐**이다.

1. **같은 레시피 ID, 표기만 다름**
2. **매콤·얼큰·매운·빨간·마라·고추장·양념 접두가 붙음** (접두를 떼면 유아식 이름과 같음)
3. **성인식 쪽에 양념·재료가 추가됨** — 유아식 이름이 성인식 이름에 포함되는 방향만 인정한다

```
② 안동찜닭      →  매콤안동찜닭      ✓
② 영양찜닭      →  매콤영양찜닭      ✓
② 로제닭볶음    →  마라로제닭볶음     ✓
③ 진미채       →  양념진미채        ✓
③ 계란장조림    →  꽈리고추계란장조림   ✓

③ 삼색콩나물무침 →  콩나물무침        ✗  (성인식이 더 단순해지는 방향은 인정 안 함)
④ 니모어묵국    →  부대찌개          ✗
④ 순살삼계탕    →  돈육고추장찌개      ✗
```

**④ 메뉴 자체 교체는 재현하지 않는다.** 납품처 피드백에 따른 비정기 이벤트라 예측이 불가능하다. **유아식과 동일하게 두고 담당자가 후처리한다.**

### 9-4. 김치 교체 ⚠ 문서에 없음

`[확정]` 인터뷰 문서에 없던 규칙이다.

```
유아식 백김치  →  성인식 매운 김치 (배추김치·열무김치·깍두기)   44건
성인식 백김치  →  유아식 매운 김치                              1건
```

담당자 확인 문구:
> "키즈 백김치로 구성될 경우 성인식은 **월 2회 정도** 열무김치로 변경"

**유아식이 백김치인 날 중 월 2회만** 성인식에서 매운 김치로 바꾼다. 무조건 바꾸면 과다 적용이다.

### 9-5. 밥

`[확정]` **밥은 유아식과 성인식이 동일하다.** 교체하지 않는다.

> 데이터상 22건이 달랐으나 16건이 2025년 8월 한 달에 몰린 이상치였다. 나머지 12개월을 합쳐 6건뿐이다.
> 담당자 확인 문구: "밥은 동일하게 진행"

## 10. 자동화 제외 영역

`[문서]` 다음은 규칙화되어 있지 않으므로 자동 생성하지 않는다. 초안 생성 후 담당자가 손보는 영역으로 남긴다.

| 항목 | 설명 |
|---|---|
| 제철 식재료·신메뉴 | 담당자가 그달의 제철 재료를 보고 개발·교체한다. 실측으로도 월 10~13종이 이력에 없는 신메뉴다 |
| 납품처별 개별 요구 | 매운맛 정도·메뉴 교체 요구가 납품처마다 다르다 |
| 조리실 사정 | 전처리 부담·조리팀 휴가 계획에 따른 조정 |
| 긴 연휴 조율 | 원과 협의 사항 |
| 성인식 메뉴 자체 교체 | §9-3 |

**이 영역이 재현율의 상한을 규정한다.** 월 10~13종의 신메뉴는 생성기가 맞힐 수 없는 몫이다.

## 12. 검증 방식

`[문서]` **재현 테스트**를 필수 기능으로 둔다.

과거 달을 지정해 생성하고 담당자가 실제로 짠 식단과 대조한다. 이때 **대상 월 직전까지의 이력만 사용**해야 한다(정보 누설 방지).

### 12-1. 측정 지표 4가지

| 지표 | 의미 | 합격선 |
|---|---|---|
| ① 하드 제약 위반 건수 | §3의 규칙을 어겼는가 | **0건** |
| ② 메뉴 집합 일치율 | 날짜는 달라도 같은 메뉴를 썼는가 | 참고 |
| ③ 단백질·조리방식 구성 일치율 | 비슷한 성격의 식단인가 | 참고 |
| ④ 칸 단위 완전일치율 | 날짜까지 같은가 | 참고 |

**①이 0이어야 하고, ②③이 높으면 담당자가 손볼 게 적다는 뜻이다.**

④는 낮게 나오는 것이 정상이다. 같은 제약을 만족하는 조합이 여러 개라 날짜까지 맞출 이유가 없다. 완전일치가 목표가 아니라 **담당자의 수정 횟수 최소화**가 목표다.

### 12-2. 현재 성적 (v1.0)

```
2026-07   하드제약 0건 · 메뉴집합 62.2% · 완전일치 6.3%
2026-08   하드제약 0건 · 메뉴집합 50.0% · 완전일치 8.3%
          (8월이 낮은 이유: 실제 사용 88종 중 13종이 이력에 없는 신메뉴)
2026-11   배치 실패 0일 · 완조리 메인 2일 · 도시락김 2회(금) · 성인식 상이율 4.0%
```

## 부록 B. 데이터 정합성 검증

`[문서]` 담당자가 인정한 실제 오류 유형이 있으므로 산출물에 다음 검증을 포함한다.

1. 레시피 재료 ↔ 알레르기 번호 정합성 (재료에 없는데 번호가 붙어 있거나 그 반대)
2. 같은 날 최우선 알레르기 중복 경고
3. 자재사용내역 중복 — 레시피 시트에서의 중복은 입력 실수를 의미하므로 별도 경고
4. 식단표의 셀 색상 표시는 무시한다 (가독성용이며 의미 없음)

단 **간접 함유는 경고 대상이 아니다.** 마요네즈의 계란, 굴소스의 조개처럼 시판 가공품 안에 들어 있는 성분은 정상이다. 원물이 아닌 구성 성분 수준의 함유는 문제 삼지 않는다.

## 부록 C. 원본 데이터에서 발견된 오류

분석 중 발견한 것으로, 자동 교정하되 원본 수정을 권고한다.

| 유형 | 대상 | 내용 |
|---|---|---|
| 날짜 입력 오류 | 2025년 11월 파일 `11-14` 시트 | A3 날짜가 `2024-11-14`로 입력됨 (연도 오타) |
| 중복 시트 | 2026-07-16 | 시트 복제본으로 같은 레코드 7건 중복 |
| 보조 자리 배정 | 2025-12-29 성인 | `& 저염쌈장`이 반찬3(김치) 칸을 차지해 김치가 밀림 |

생산일지는 `HowToUse` §6·7에 따라 A3 날짜를 참조해 나머지 값이 채워지므로, 날짜 오류는 그 시트 전체에 영향을 준다.
