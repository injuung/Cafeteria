## 0. 코딩을 시작하기 전에 반드시 읽을 것

### 0-1. 실행시간 6분이 설계를 지배한다

Apps Script는 소비자 계정·Workspace 계정 모두 **1회 실행 6분**이 상한이다.

따라서 **완전탐색(brute force)을 하면 안 된다.** 20영업일 × 6칸 × 후보 372종을 전부 시도하면 6분 안에 끝나지 않는다.

```
필수 제약
  · 칸당 검토 후보는 상위 N개까지만 (권장 N = 12)
  · 백트래킹 깊이는 2일까지
  · 후보 정렬은 배치 시작 전에 한 번만 (매 칸마다 재정렬 금지)
```

### 0-2. SpreadsheetApp 호출을 최소화한다

셀 단위 접근은 극도로 느리다. **시트 전체를 `getValues()`로 한 번에 읽고 메모리(JS 객체)에서 처리한다.**

```javascript
// ❌ 절대 금지
for (var r = 2; r <= 700; r++) {
  var name = sheet.getRange(r, 3).getValue();   // 700회 RPC
}

// ✅
var values = sheet.getDataRange().getValues();  // 1회 RPC
for (var r = 1; r < values.length; r++) {
  var name = values[r][2];
}
```

쓰기도 마찬가지다. 2차원 배열을 만들어 `setValues()`로 한 번에 쓴다.

### 0-3. 런타임에 필요한 시트는 3개뿐이다

마스터 파일에 시트가 여러 개 있지만 **생성기가 읽어야 하는 것은 3개**다.

| 시트 | 용도 | 행수 |
|---|---|---|
| `01_레시피마스터` | 후보 풀 · 속성 | 약 760 |
| `02_별칭매핑` | 표기명 선택 | 약 860 |
| `07_보조매핑` | 부모-보조 관계 | 약 35 |

`04_편성원장`(약 3,900행)은 **읽지 않는다.** 로테이션 판단에 쓰는 최종출현일·평균간격은 이미 `01_레시피마스터`에 계산되어 있다.

## 4. 모듈별 명세

### ① `loadMaster()` → `Data`

```javascript
/**
 * @return {{
 *   recipes: Object<string, Recipe>,   // recipeId → Recipe
 *   repToId: Object<string, string>,   // 대표명 → recipeId
 *   aliasById: Object<string, Alias[]>,
 *   sidesByParent: Object<string, Array<{id, name, count, lastUsed}>>
 * }}
 */
```

`Recipe` 객체

```javascript
{
  id: 'R0123', rep: '춘장닭볶음',
  active: true,                    // C열 === 'O'
  status: '활성',
  isSide: false,
  slotMain: '메인',
  slotDist: {'메인': 12, '서브1': 1},   // M열 파싱
  proteins: ['계육'],              // O열 쉼표 분리
  cook: '볶음',
  ready: false,
  allergy: [5, 15, 21],            // U열 '.' 분리, 0이면 []
  lastSeen: '2026-07-01',          // Z열. 빈칸이면 null
  occCount: 12,
  weightG: 60,
  materialText: '닭정육(...)75%, ...',
  memo: ''
}
```

**주의사항**

- C열이 `X`면 `active = false`. 이후 모든 후보 선택에서 제외한다.
- Z열(최종출현)이 빈칸이면 `lastSeen = null` → 경과일 9999로 취급
- U열이 `'0'`이면 알레르기 없음(`[]`)
- M열 파싱: `'김치190, 서브22'` → `{김치: 190, 서브2: 2}`
  정규식 `/^(밥|메인|서브1|서브2|김치|국)(\d+)$/`

### ② `violates(data, state, date, day, slot, recipeId)` → `string | null`

하드 제약 검사기. 위반이면 사유 문자열, 통과면 `null`을 반환한다.

**검사 순서** (빠른 것부터)

```
1. 같은 날 동일 레시피 중복
2. §3-1 주재료 중복 — slot ∈ {메인,서브1,서브2,국} 일 때만.
                      day 안의 밥·김치는 비교 대상에서 제외
3. §3-2 튀김 2개 — cook === '튀김' 인 것이 이미 있으면 탈락
4. §3-3 최우선 알레르기 — 이 메뉴의 알레르기 ∩ [1,4,9,18] 각 번호에 대해
                          day 안에 같은 번호를 가진 메뉴가 이미 2개면 탈락
5. §3-4 월간 상한 — slot === '메인' 일 때만.
                    완제품이고 state.readyMain >= 3  → 탈락
                    덮밥소스류고 state.donburi >= 2   → 탈락
6. §3-5 김치 회피 — slot === '김치' 일 때만.
                    깍두기 배치 시 day에 '깍두기' 포함 메뉴가 있으면 탈락
                    배추김치 배치 시 day에 '김치' 포함(단 '깍두기' 제외) 메뉴가 있으면 탈락
                    열무김치 배치 시 day에 '열무' 포함 메뉴가 있으면 탈락
7. §6-1 도시락김 — FAVORITE_SUB2 중 하나면
                   금요일이 아니면 탈락 / 이번 달 이미 2회면 탈락
8. §4 로테이션 — 경과일 < 최소간격이면 탈락
                 단 국 자리의 SOUP_FAVORITES는 월 2회까지 로테이션 무시
                 미역국류는 그 주에 이미 있으면 탈락
```

> **이 함수는 단독으로 테스트할 수 있어야 한다.** 과거 실제 편성을 넣어 위반 건수를 세는 것이 가장 좋은 검증이다. 담당자 실제 편성에서는 최근 1년 기준 월 2~3건 수준의 위반이 나온다(경계 사례).

**덮밥소스류 판정** — 대표명에 `'덮밥소스'` 문자열이 포함되면 해당.

**샐러드 판정** — `cook === '샐러드'` 또는 대표명에 `'샐러드'` 포함.

### ③ `score(data, state, date, day, slot, recipeId)` → `number`

```javascript
var s = 0;

// 1. 로테이션 목표 근접도
var [lo, hi] = ROTATION[slot];              // 샐러드면 SALAD_ROTATION
var g = Math.min(gap(recipeId, date), 400); // 경과일
if (g >= hi) s += WEIGHT.gapFit * Math.min(1.0, (g - hi) / 120 + 1.0);
else         s += WEIGHT.gapFit * Math.max(0, (g - lo) / Math.max(1, hi - lo));

// 2. 같은 날 조리방식 중복
s += WEIGHT.cookRepeat * (day 안에서 같은 cook 개수);

// 3. 같은 주 조리방식 / 단백질 반복 (0~1 정규화)
s += WEIGHT.cookWeek    * Math.min(주간 같은 cook 수, 4) / 4;
s += WEIGHT.proteinWeek * Math.min(주간 단백질 겹침 수, 5) / 5;

// 4. §4-1 완조리·닭 메인인 날 소고기 국 가점
if (slot === '국' && day['메인']) {
  var m = data.recipes[day['메인']];
  if ((m.ready || m.proteins.indexOf('계육') >= 0)
      && this.proteins.indexOf('우육') >= 0) s += WEIGHT.beefSoup;
  if (대표명에 '미역국' 포함 && 그 주에 미역국 없음) s += WEIGHT.seaweedWeekly;
}

// 5. 완조리 메인 억제 — 목표 2회까지는 중립, 넘으면 감점
if (slot === '메인' && ready && state.readyMain >= READY_MAIN_TARGET)
  s += WEIGHT.readyPenalty * (1 + state.readyMain - READY_MAIN_TARGET);

// 6. 선호 서브2
if (slot === '서브2' && FAVORITE_SUB2 중 하나 포함) s += WEIGHT.favorite;

// 7. 과거 사용빈도 prior
s += WEIGHT.freqPrior * Math.min(occCount, 20) / 20;

return s;
```

> **5번 주의** — 목표 미만일 때 감점하면 완조리 메인이 0회가 되어 담당자 실적(월 1~2회)과 어긋난다. 반드시 목표 이상일 때만 감점한다.

### ⑨ `toAdult(data, plan, swapMap)` → `adultPlan`

**`buildAdultMap()`이 먼저 실행된다.**

```
대상 월 직전 6개월(§9-1)의 유아↔성인 동일일자 비교
  for each 날짜, for each slot ∈ ADULT_SWAP_SLOTS:
      유아[slot] !== 성인[slot] 이면
          isVariation(유아id, 성인id) 가 true 일 때만 swapMap 에 기록
          false 면 버린다 (§9-3 ④ 메뉴 자체 교체)
```

**`isVariation(kidId, adultId)`** — 이 함수가 §9-3의 핵심이다.

```javascript
function isVariation(data, kidId, adultId) {
  if (kidId === adultId) return true;                     // ① 같은 레시피
  var a = data.recipes[kidId].rep;
  var b = data.recipes[adultId].rep;
  var MOD = /^(매콤한|매콤|얼큰|매운|빨간|마라|고추장|양념)/;
  if (MOD.test(b) && b.replace(MOD, '') === a) return true;  // ② 매운맛 접두
  if (b.indexOf(a) >= 0) return true;                        // ③ 양념·재료 추가
  return false;                                              // ④ 메뉴 교체 → 제외
}
```

> **③의 방향에 주의한다.** `b.indexOf(a) >= 0` 이어야 한다. 즉 **성인식 이름이 유아식 이름을 포함하는 방향만** 인정한다.
> `a.indexOf(b) >= 0` 까지 허용하면 `삼색콩나물무침 → 콩나물무침`처럼 성인식이 더 단순해지는 케이스가 잘못 잡힌다.

**`toAdult()` 본체**

```
kimchiUsed = 0
for each 날짜:
  for each slot:
      if slot === '밥':
          그대로 둔다 (§9-5)
          continue
      if slot ∈ ADULT_SWAP_SLOTS:
          swapMap[(slot, id)] 가 있고
          교체율(교체횟수 / 관측횟수) >= 0.5 이면
              후보 중 active === true 이고 violates() 통과하는 첫 번째로 교체
      if 교체 안 됐고 slot === '김치' 이고 유아가 백김치이고
         kimchiUsed < KIMCHI_SWAP_MONTHLY:
              SPICY_KIMCHI 중 violates() 통과하는 첫 번째로 교체
              kimchiUsed += 1
```

> **교체 후보도 `active` 검사를 해야 한다.** 담당자가 X로 끈 메뉴가 성인식에만 슬쩍 들어가는 버그가 있었다.
>
> 김치 교체 시 `violates()`는 **월간 상한·로테이션을 무시하고 당일 제약만** 봐야 한다. 더미 state를 넘긴다.

### ⑩ `writeWorkbook()` — 출력

생산일지와 동일한 구조·서식으로 만든다. 상세 서식값은 부록 A 참조.

**시트 순서**

```
글로벌리더스&석식식단표 · 유아식단표 · 레시피북 · MM-DD(일자별) · 선택근거 · HowToUse
```

**핵심** — 자재사용내역·알러지표기·메모는 **값을 직접 쓰지 않고 수식으로 쓴다.** 담당자가 메뉴명을 바꾸면 자동으로 따라오게 하기 위해서다. 원본 생산일지와 동일한 동작이다.

```
자재사용내역 (G열)
=IFERROR(IF(INDEX(레시피북!$C$2:$H$N,MATCH($D3,레시피북!$C$2:$C$N,0),6)="","",
            INDEX(레시피북!$C$2:$H$N,MATCH($D3,레시피북!$C$2:$C$N,0),6)),"")

알러지표기 (H열)
=IFERROR(IF(INDEX(레시피북!$D$2:$J$N,MATCH($D3,레시피북!$C$2:$C$N,0),6)="","",
            INDEX(레시피북!$D$2:$J$N,MATCH($D3,레시피북!$C$2:$C$N,0),6)),"")

메모 (L열)
=IFERROR(IF(INDEX(레시피북!$C$2:$J$N,MATCH($D3,레시피북!$C$2:$C$N,0),8)="","",
            INDEX(레시피북!$C$2:$J$N,MATCH($D3,레시피북!$C$2:$C$N,0),8)),"")
```

`N`은 레시피북 시트의 마지막 행 번호다. **열 오프셋이 레시피북 시트의 열 배치에 의존하므로 반드시 아래 순서를 지킨다.**

```
레시피북 시트 열 배치 (변경 금지)
A No. / B 품목 / C 품명 / D 온라인(g) / E 급식(g)
F 온라인 중/대(EA) / G 급식(EA) / H 자재사용내역 / I 알러지표기 / J 메모
```

**별칭도 레시피북 시트에 각각 한 행으로 등재한다.** 성인식에 `매콤안동찜닭`이 쓰이면 그 이름으로도 조회가 되어야 한다.

**제공인원·총생산량은 담당자 입력란**이다. 제공인원 칸을 노란색으로 칠하고, 총생산량은 `=IF($E3="","",IF($J3="","",$E3*$J3))` 수식을 넣는다.

## 7. Gemini에 요청하는 순서

한 번에 전부 요청하면 뒤로 갈수록 규칙이 흐려진다. **아래 순서로 쪼개서 요청한다.**

```
1차   §1 데이터 구조 + ① loadMaster()
      → 시트를 읽어 Recipe 객체 배열을 만들고 로그로 검증

2차   ② violates() + §6-1 테스트 케이스 10개
      → 테스트가 전부 통과할 때까지 이 함수만 붙든다
      ★ 여기가 품질의 8할이다. 서두르지 말 것

3차   ③ score() + ④ buildCalendar() + §6-2 테스트

4차   ⑤ placeDay() + ⑥ generateMonth()
      → 배치 실패 0일이 나올 때까지

5차   ⑦ pickLabel() + ⑧ attachSides() + ⑨ toAdult() + §6-3 테스트

6차   ⑩ writeWorkbook()
      → 서식은 부록 A 그대로

7차   ⑪ runReproTest() + §5 UI
```

각 차수마다 **"이전 차수의 함수 시그니처를 그대로 쓰라"**고 명시한다. 그러지 않으면 매번 다시 짜서 앞 내용이 어긋난다.

## 부록 C. 참고 구현

Python 프로토타입이 `식단표생성기.zip`에 있다. 이 명세의 모든 규칙이 동작하는 상태로 구현되어 있으므로, 로직이 애매할 때 참고하면 된다.

```
rules.py        상수 · 데이터 로더 · violates() · score()
planner.py      buildCalendar() · placeDay() · generateMonth() ·
                attachSides() · buildAdultMap() · toAdult()
export_prod.py  writeWorkbook()
verify.py       runReproTest()
```

단 Python 판은 실행시간 제약이 없어 §0-1의 제한을 적용하지 않은 부분이 있다. Apps Script로 옮길 때는 `TOP_N` 제한을 반드시 지킨다.
