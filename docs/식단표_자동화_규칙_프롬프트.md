# 더바른푸드 식단표 자동 생성 — 작업 지시 프롬프트

> 아래 내용을 새 대화창에 그대로 붙여넣어 사용하세요.
> (출처: 2026-08-18 더바른푸드 3차 컨설팅 담당자 인터뷰 녹취록에서 추출한 업무 규칙)

---

## 0. 역할과 목표

너는 어린이·초등·성인 대상 단체급식 업체 **더바른푸드**의 월간 식단표 초안을 생성하는 시스템을 만드는 역할이다.

**목표 수준은 "완전 자동화"가 아니다.** 담당자가 수작업으로 만드는 결과를 100점이라 할 때, **60~70점 수준의 초안**을 만들어 담당자가 "손만 보면 되는" 상태로 넘기는 것이 목표다. 애매한 판단은 무리해서 결정하지 말고, 초안에 표시하고 담당자 확인 항목으로 남겨라.

---

## 1. 입력 데이터

| 데이터 | 역할 |
|---|---|
| **레시피북(구 "온라인 반찬")** | 전체 메뉴 마스터 DB. 메뉴명 · 레시피 · 자재사용내역 · 알레르기 번호 보유. 여기에 있는 것이 사용 가능한 메뉴 풀의 전부. |
| **과거 식단표** (최소 최근 1년) | 로테이션 주기, 메인/서브 위치, 실제 사용 이력 파악용 |
| **생산일지** (일별) | 식단표 확정 후 생성되는 일별 문서. 레시피·알레르기가 함수로 자동 연동됨 |

**중요:** 신메뉴는 생산일지를 작성하는 과정에서 레시피북에 사후 추가된다. 따라서 레시피북은 항상 최신이 아닐 수 있다.

---

## 2. 담당자의 실제 작업 순서 (이 순서를 그대로 따를 것)

```
① 식단표(월 단위 큰 틀) 구성          ← 자동화 핵심 대상
② 그 달의 신메뉴/제철 메뉴 검토·교체
③ 일별 생산일지 작성
④ 레시피·알레르기 정보 연동 (③과 동시 진행)
```

생산일지에서 식단이 나오는 것이 **아니라**, 식단표가 먼저 완성된 뒤 생산일지가 파생된다. 순서를 뒤집지 마라.

또한 실무에서는 **3개월 치를 한 묶음으로 미리 작업**한다. 예: 6월에 7·8·9월분을 짜둔다. 새 달을 짤 때는 **직전 2~3개월 식단과 비교**하여 중복을 피한다.

---

## 3. 1일 식단 구조

```
밥 + 메인반찬 1 + 서브반찬 2 + 국 1 + 김치 1
```

- 서브반찬은 **2개**다 (김치를 서브에 포함해 3개로 세지 말 것).
- **서브1**과 **서브2**는 성격이 다르다. 서브1은 메인급으로 관리, 서브2는 선호 반찬·나물·샐러드+드레싱·김류가 들어가는 자리다.

### 3-1. 결정 우선순위 (반드시 이 순서)

```
메인반찬 → 국 → 서브반찬 → 밥 → 김치
```

메인이 절대 기준이다. 충돌이 생기면 **메인을 고정하고 나머지를 바꾼다.**

### 3-2. 메인/서브 분류가 데이터에 없다

식단표에는 메인/서브 구분 컬럼이 **명시돼 있지 않다.** (예전엔 구분했으나 관리가 복잡해 중단함.) 따라서 과거 식단표에서 **메뉴가 놓인 자리(열 위치·순서)**를 학습해 메인/서브/국/김치를 분류해야 한다. 메뉴명만으로 "김치전이 김치인가 반찬인가" 같은 판단을 하려 하지 마라.

### 3-3. 조리 형태별 조합 규칙

- **스튜류 = 조림 계열 메인**으로 분류한다.
- 메인이 **조림 계열**이면 → 서브는 물기 적은(매트한) 반찬 위주, 국은 **건더기가 실한 것**(어묵국, 굴린만두국 등)으로 배치.
- 메인이 **덮밥소스류**(하이라이스, 소고기계란덮밥소스 등)이면 → 서브는 **메인과 다른 단백질**로 구성, 국은 건더기 실한 것으로 배치.

---

## 4. 하드 제약 (반드시 위반 없이 생성)

### 4-1. 같은 날 주재료 중복 금지

- 메인 주재료 ↔ 서브1·서브2 주재료
- 서브 ↔ 국
- 메인 ↔ 국
- 예: 메인이 소고기면 국에 소고기 안 됨. 메인에 계란이 들어가면 보조 메뉴에도 계란 안 됨.

> 이유는 다양성 확보만이 아니라, **알레르기·종교적 사유로 특정 재료를 못 먹는 아이가 그날 아예 먹을 게 없어지는 상황을 막기 위해서**다. 과거에는 이 규칙 없이 단순 로테이션만 했으나, 요구사항이 세분화되며 필수 규칙이 되었다.

### 4-2. 튀김 2개 금지

같은 날 튀김류가 두 가지 이상 나오면 안 된다.

### 4-3. 월간 횟수 상한

| 항목 | 상한 |
|---|---|
| 완조리(완제품·냉동) 메뉴가 **메인**으로 들어가는 경우 | 월 2회, 최대 3회 |
| 덮밥소스류 | 월 2회 이하 |

### 4-4. 김치 중복 회피

김치는 배추김치 · 깍두기 · 백김치가 자유롭게 반복된다. 단, **다른 메뉴에 김치 종류가 재료로 쓰이면 그 김치를 피한다.**
예: 그날 메인이 "참치깍두기볶음"이면 김치는 깍두기 대신 배추김치로 변경.

## 5. 로테이션 주기

| 구분 | 기본 주기 | 예외 |
|---|---|---|
| **메인반찬** | 2.5~3개월 | 웬만하면 예외 없음 |
| **서브1** | 3개월 (메인과 동일) | 메뉴 구성상 부득이하면 2~2.5개월 허용 |
| **서브2** | 선호 메뉴는 **월 1~2회, 다음 달에도 반복 가능** | 김자반, 도시락김 등 |
| **국** | 2.5~3개월 | 아래 5-1 참조 |
| **샐러드류** | 3개월 목표 | 부득이하면 2~2.5개월 |
| **김치** | 제한 없음 | 4-4 규칙만 준수 |

### 5-1. 국의 예외 규칙 (중요)

- **미역국류는 주 1회 기본 편성**을 원한다.
- **소고기미역국·소고기무국**은 선호도가 높아 **월 2회**까지 허용.
- 특히 **메인이 완조리/냉동 제품이거나 닭고기 메뉴인 날**에는 소고기미역국처럼 소고기가 들어간 국을 의도적으로 배치한다. → "여기는 냉동식품만 쓰는 곳이 아니구나" 하는 학부모 안심 효과를 노린 배치다. 이건 단순 선호가 아니라 **의도된 패턴**이므로 규칙으로 구현할 것.
- 그 주의 구성이 전반적으로 만족스럽지 못할 것 같으면 선호 메뉴를 주기와 무관하게 중복 편성한다.

즉 **기본 로테이션 + 인기/보정 메뉴 예외**를 함께 적용해야 한다.

---

## 6. 요일·주차 기반 특수 규칙

| 규칙 | 내용 |
|---|---|
| **매월 3주차 금요일** | 아이들 생일파티 메뉴 → **볶음밥 + 스파게티** 계열 편성 (고정) |
| **금요일, 월 2회** | **도시락김** 편성. 직원 연차 사용을 수월하게 하기 위한 배치 — 조리·전처리가 필요 없고 포장팀이 미리 작업 가능하기 때문 |

정기 로테이션 규칙은 위 두 개가 전부다. 그 외에 조리실 사정(전처리 난이도, 조리팀 휴가 계획)에 따른 조정이 있으나 **패턴화돼 있지 않으므로 자동화 대상에서 제외**하고 담당자 후처리 영역으로 남긴다.

## 7. 알레르기 규칙

### 7-1. 우선순위가 다르다 — 모든 번호를 동일하게 취급하지 마라

| 등급 | 알레르기 번호 | 처리 |
|---|---|---|
| **최우선 회피** | **1(난류/계란), 4(견과류), 9(새우), 18(조개류)** | 같은 날 여러 메뉴에 중복되지 않도록 최대한 배제. 메뉴 구성상 부득이한 경우만 예외 |
| **무시(중복 허용)** | 10(돼지고기), 15(닭고기), 16(쇠고기) | 대부분의 식단에 들어갈 수밖에 없음. **번호 중복이 아니라 실제 주재료 중복(4-1)으로 관리** |
| **무시** | 아황산류 | 통조림 보존료 등으로 들어가는 것이라 신경 쓰지 않음 |
| **판단 필요** | 미량 함유·혼입 가능성 표시 | 원물 계란·우유가 아니라 구성 성분에 포함된 정도(예: 분말카레의 혼입 가능성 표시)는 중복돼도 문제 삼지 않음 |

> 18번은 굴소스 등 해산물 계열에서 자주 붙는다. 4번은 견과류다. 번호 정의는 식단표 하단 범례 표기를 기준으로 확인할 것.

### 7-2. 데이터 정합성 검증 기능을 반드시 넣어라

담당자가 인정한 **실제 존재하는 오류 유형**:

- 레시피에서 굴소스를 뺐는데 **18번 알레르기 번호가 그대로 남아 있는** 경우
- 복사·붙여넣기로 메뉴를 만들면서 **알레르기 정보가 함께 수정되지 않은** 경우
- 메뉴를 지웠다 바꿨는데 **레시피 갱신을 누락**한 경우

따라서 자동화 산출물에는 다음 검증이 포함되어야 한다:

1. 레시피 재료 ↔ 알레르기 번호 **정합성 체크** (재료에 없는데 번호가 붙어 있거나 그 반대)
2. 같은 날 최우선 알레르기(1/4/9/18) **중복 경고**
3. 자재사용내역 중복 체크 — 기존 파일에서는 중복 시 **주황색 표시**로 잡고 있음. 단, 레시피 시트에서의 중복은 **입력 실수**를 의미하므로 별도 경고로 다뤄야 한다.
4. 식단표의 셀 **색상 표시는 무시**해도 된다 (담당자가 가독성 위해 임의로 칠한 것, 의미 없음).

## 8. 메뉴 명칭이 유동적이다 — 중복 판정의 함정

**메뉴명으로 동일 메뉴 여부를 판단하면 안 된다.**

같은 날 "볶음+볶음", "찜+찜"처럼 조리방식이 겹치면 메뉴명이 단조로워 보이므로, 담당자는 **레시피는 그대로 두고 이름만 바꾼다.**

- 돈사태양념찜 + 어묵채소찜 → 앞을 "돈사태양념볶음"으로 변경
- 북어콩나물무침 ↔ 북어콩나물조림 (같은 레시피, 달마다 이름만 다름)
- 간장주먹밥 ↔ 뭉치지 않은 형태 (레시피 동일)
- 짜장덮밥소스 → 소고기짜장덮밥소스 / 유니짜장덮밥소스 (이름만 바꿔 돌림)

**→ 구현 원칙: 중복 판정과 로테이션 주기 계산은 메뉴명이 아니라 `레시피 ID` 또는 `주재료 조합` 기준으로 하라.** 과거 데이터에 "메뉴는 하나인데 이름이 두 개"인 케이스가 존재한다는 전제로 정규화 매핑 테이블을 먼저 만들어야 한다.

조리방식 중복은 **금지가 아니라 감점 요소**다. 어느 정도 허용되지만 반복되면 명칭 변경으로 해소한다.

---

## 9. 메뉴 풀 유효성 판단 — 과거 데이터를 그대로 학습하지 마라

레시피북에 등재돼 있다고 해서 현재 쓰는 메뉴가 아니다.

**판정 기준: 최근 약 1년간 식단표/생산일지에 한 번도 등장하지 않은 메뉴 = 비활성(사실상 폐지) 메뉴로 간주.**
- 3개월 미출현 정도로는 폐지 판정 금지 (정상 로테이션 범위).
- 2025년 9월분 또는 2025년 1월분부터의 생산일지·식단표와 레시피북을 대조해 생존 메뉴를 추출할 것.

### 9-1. 실제 제외 이력 (참고 — 같은 성격의 메뉴는 보수적으로 다룰 것)

| 메뉴 | 사유 |
|---|---|
| 유산슬덮밥소스 | "중식이 너무 많다"는 납품처 의견 → 삭제 |
| 짜장덮밥소스류 | 같은 사유로 빈도 축소. 대신 닭볶음에 짜장 성분을 활용하는 식으로 변형 |
| 깐풍두부, 짬뽕국 등 | 중식 데이 구성 자체를 축소 |
| 꼬마핫도그 | 완제품이라 맛이 떨어져 제외 |
| 소고기미역국(일시) | 요오드 성분 과다 섭취 뉴스 이슈 → 한동안 제외 후 조용히 복귀 |

**제외 트리거:** 서로 다른 납품처 **2곳 이상에서 동일한 클레임**이 나오거나, 특정 성분이 뉴스 이슈가 되거나, 주요 거래처(어학원 등)에서 클레임이 들어오면 해당 메뉴를 당분간 제외한다. → 자동화 시스템에는 **수동 제외/블랙리스트 입력란**이 반드시 있어야 한다.

## 10. 유아식 vs 성인·초등식

**유아식이 베이스다.** 유아 식단표를 먼저 완성한 뒤 이를 변형해 성인·초등(글로벌리더스 등) 식단을 만든다.

변형 유형은 두 가지다:

1. **간·매운맛 조정** (대부분) — 기준은 "너무 슴슴하다". 고춧가루 추가 등으로 해결하며, 레시피북에 없는 변형도 발생한다.
   예: 소고기무국 → **얼큰소고기무국**
2. **메뉴 자체 교체** (월 1회 정도) — 형태가 지나치게 유아식이라 성인이 먹기 부적절한 경우.
   예: 소고기소보로(다진 형태) → **소불고기**

**주의:** 변형 빈도와 정도는 **납품처(식당)마다 다르므로 일률적 규칙으로 정의 불가.** 패턴 학습은 **최근 6개월치**(3개월 단위 × 2회분) 유아식/성인식 식단표 비교로 하라. 그 이상 오래된 데이터를 넣으면 "우연히 6개월에 한 번 이렇게 됐네" 같은 무의미한 규칙까지 학습하므로 금지.

---

## 11. 부가 규칙

- **드레싱/소스**: 그린샐러드에 유자키위드레싱/유자드레싱 등을 붙이는데, **고정 규칙은 없고** 그 주·그날 메뉴와 겹치지 않도록 바꾼다. 중복 회피 로직만 적용하고 고정 매핑은 만들지 마라.
- **제철 식재료·신메뉴**: 담당자가 그달의 제철 재료를 보고 메뉴를 개발하거나 업그레이드해 교체한다. 자동 생성 대상이 아니며, 초안 생성 후 담당자가 끼워 넣는 슬롯으로 남겨둔다.

---

## 12. 산출물

기존 엑셀 양식과 동일한 구조로 출력한다:

1. **월간 식단표** (일자별 × 밥/메인/서브1/서브2/국/김치)
2. **일별 생산일지** 형식
3. **자재사용내역 / 알레르기 표기** (레시피북에서 자동 연동)
4. **검증 리포트** — 위반·경고 항목 목록 (알레르기 중복, 주재료 중복, 조리방식 반복, 로테이션 주기 위반, 월 횟수 초과, 정합성 오류)

각 편성 칸에는 **왜 이 메뉴가 선택됐는지 근거**(직전 출현일, 주재료, 알레르기 번호)를 함께 남겨 담당자가 빠르게 검수할 수 있게 하라.

---

## 13. 구현 권장 순서

```
1) 레시피북 정규화 — 레시피 ID, 주재료, 조리방식, 알레르기 번호, 완제품 여부 태깅
2) 메뉴명 → 레시피 ID 매핑 테이블 생성 (이름만 다른 동일 메뉴 통합)
3) 과거 식단표 파싱 → 자리 기반으로 메인/서브1/서브2/국/김치 라벨링
4) 메뉴별 최종 출현일 · 출현 빈도 산출 → 1년 미출현 메뉴 비활성 처리
5) 캘린더 골격 생성 (3주차 금요일 생일파티, 금요일 도시락김 월 2회 선배치)
6) 메인 배치 → 국 배치 → 서브 배치 → 밥 → 김치 (제약 위반 시 백트래킹)
7) 검증 리포트 생성
8) 유아식 → 성인·초등식 변형본 생성
```

---

## 14. 아직 확정되지 않아 담당자 확인이 필요한 항목

초안 생성 후 아래는 자동 판단하지 말고 **질문 목록으로 남겨라**:

- 조리실 사정(전처리 부담, 휴가 계획)에 따른 조정
- 그달의 제철 식재료 및 신메뉴 반영
- 납품처별 개별 요구사항(매운맛 정도, 메뉴 교체 요구)
- 1년 경계선에 걸친 애매한 메뉴의 활성/비활성 판정
- 클레임·이슈로 인한 일시 제외 메뉴 목록

---

## 15. 검증 방식

프로토타입 결과물은 **담당자가 실제로 짠 같은 달 식단과 비교**해 일치도를 측정한다. 목표는 완전 일치가 아니라 **담당자의 수정 횟수 최소화**다. 수정된 항목을 수집해 규칙을 역으로 보완하는 반복 개선 구조로 갈 것.
